# 官方預報、位置推算與選車跟隨

2026-11-18 的新增產品功能。既有兒童粉彩玩具城市與地理來源保留；可選「模擬遊玩」或「官方預報」。**官方模式的到／離站預報是真資料，位置和內部班次身份仍是推算。** 港鐵沒有在 Next Train API 提供列車 GPS、實際車號或車款；不能把畫面當成精確真車定位，也不能保證真車一定與動畫同秒到站。

## 資料與欄位

已重新讀取港鐵 Next Train Data Dictionary v1.7（2025-03-13）：https://opendata.mtr.com.hk/doc/Next_Train_DataDictionary_v1.7.pdf 。PDF 不複製入 repo。status=1 正常、0 錯誤／提示；方向及可用終點按文件明確表處理，不靠 CSV UT/DT 猜測。ttnt、valid、source 是 dummy，不用來做位置／倒數；用 time 的香港時間解析值。

東鐵樣本實際使用 `timeType`，文件寫 `timetype`；程式只明確兼容這兩個已知寫法，原始 JSON 都保留。A=到站，D=離站；缺少或兩者衝突則為一般到／離站預報，不假設為到站。route=RAC 使用真正馬場支線幾何。樣本來源及真正／合成案例分別在 data/raw/next-train-20261118/README.md。

拓撲資料 121 個線路站鍵、98 站碼（120 個 CSV 鍵加文件支援的 RAC）、30 條方向／分支路徑，來源和逐邊檢查見 live-network-audit.md。東涌東／西仍未開通，不參與預報查詢。站點對軌道的距離是推斷投影，最大 43m 是**站點投影差**，不是列車定位精度。

## Proxy、輪詢及新鮮度

- Hono GET `/api/trains?line=all|<LINE>&cursor=<index>&priority=<station>`：每次輪詢最多 8 個已知線路／站鍵，回傳該範圍已快取的列車推算、各線狀態、coverage、nextCursor、serverTime。
- 頁面開啟官方模式時逐批讀取；一批完成後約 1 秒下一批，背景分頁約 10 秒。關閉模式／頁面就停止新查詢。這是需要時更新，不是無人瀏覽時運作的全天後台排程。
- 每個 Node process／Worker isolate 最多 **4 次起始請求／秒、240 次未快取請求／分鐘**，每個請求範圍最多 3 個並發；同一請求內相同 key in-flight 合併、TTL 15 秒、timeout 6.5 秒、失敗按 key 指數退避 5–60 秒；429 最少停 30 秒並遵守較長 Retry-After。這是本站自行設定的上限，不冒稱港鐵公布的配額。
- 正式 Worker 以 D1 共享原始預報快取和虛擬身份，讀取最近 180 秒資料；沒有把 DB 當成全世界原子限速器。不同 isolate／地區的總請求可能累加。目前 Site 訪問範圍保留 owner-only。
- 全港 121 個站鍵單是 4 rps 下限就約 31 秒，另加網絡和重試；**不聲稱全港每秒同步更新**。選一條線可更快輪完。UI 顯示實際已更新站數、來源時間及中斷；回應成功不等於每站資料最新。
- 官方資料超過 75 秒會顯示資料中斷／續推並漸淡，105 秒後消失；不從 fixture 或模擬模式補充。API 不進 service-worker cache。

## 虛擬班次與運動

1. 每個觀測取 line、已驗證 UP/DOWN、station、dest、route、plat、time、官方時間。只保留有可用來源路徑、時間合理及未開站以外的觀測；未知目的地／路徑計入 diagnostics，暫不畫出。
2. 分支特定觀測優先，公用站的歧義觀測最多配一個群組；羅湖／落馬洲、寶琳／康城及馬場分開。不能確認北端分支的南行預報，不外推到未觀測的北端分支。
3. 相鄰站至少兩組相容目的地、順序及預報時間差一致時，估計該方向站間的**預報偏移**；它不是實測行車時間。其他站間使用 data/config/segment_times.json 的可替換模型：預設 15m/s、最短 45 秒、停站 25 秒。全部標記 model-parameter-not-official。
4. 用站序、相鄰預報偏移、FIFO／最小行程條件合併觀測，保留內部 virtual- ID；ID 不是港鐵車號。舊／新群組以相同路徑、方向、終點、共站時間和位置連續性匹配；不把共站預報複製成兩條支線的車。
5. 官方時間是錨點；停站／加速／減速用連續曲線。凍結一組預報時，動畫在其時間抵達對應軌道投影站點。時間修訂時從目前位置重新平滑追趕，受推算軌跡速度的上限控制，不反向或瞬移；追不上則標「校正中」。官方改期和速度連續性可能無法同時嚴格滿足，所以不保證物理真車到站秒數。
6. 官方模式固定真實時間 1×，不容許加速或暫停實時時鐘；模擬模式保留暫停／1×3×10×。兩種列車不混用。未能繼續配對原班次時提示使用者，不自動換另一架。

## 位置、選車與車款

- 點圖中的車或用「揀一架列車遊城市」可選明確的虛擬預報班次／模擬車；鏡頭跟隨該 ID。
- 按「定位跟車」後才 watchPosition，可關閉。GPS 座標及精度只留在瀏覽器；只查附近線路／站碼。推薦 5km 內附近推算列車後跟隨，明示不能確認使用者乘搭哪架真車；GPS 在地下失效或拒絕時保留手動清單。
- 全線為程式原創的點、線、色塊及立體幾何玩具；代表車款來源、混合車隊及型號限制見 rolling-stock.md。實際班次車款不能由 API 得知。

## 驗證及限制

單元測試使用真實記錄的方向／分支／空看板／錯誤，以及明確命名的延誤、離站、timeout 和中斷合成案例；覆蓋合併、ID 延續、指定時間錨點、平滑校正、限速／合併／退避。沒有列車 GPS ground truth，不聲稱已測出真車位置誤差、總真車數或完全正確身份。密集班次、預報修訂、未回傳車站與平台仍可能導致合併歧義或漏畫；coverage／時間／推算標記保留，待日後實地與更多回應核對。

列車清單採用開啟時快照固定順序，避免新預報令按鈕在點選時移位；可按更新清單。選擇後仍用最新同一 ID 的預報跟隨；身份消失時不換車。返回背景暫停的分頁時按真實時鐘重同步位置，不重播無人觀看期間的舊動畫。

## 雲端共享快取修正

正式環境全網核對發現 isolate/edge cache 不能保證各批完整累積（121 鍵已輪詢但讀回覆蓋會倒退）。因此正式 Site 以 D1 的 `rail_observations` 按站鍵 upsert、`rail_trip_cache` 保存虛擬身份；每次讀取完整選定範圍再估算，避免不同執行個體互相覆蓋整條線的快取。15 秒 TTL／75–105 秒新鮮度界線不變。D1 只存官方公開預報與內部 ID，不存使用者 GPS 或兒童資料。Node 無 D1 時保持 process cache；正式頁面若 D1 失效會明示共享快取更新中及實際 coverage，不冒充全網已更新。

資料表由 drizzle-kit 0.31.10／drizzle-orm 0.45.2 生成的 schema-only migration 建立，隨 Sites 發佈套用；請求處理不建立資料表。不同 key 按原始官方時間與輪詢時間做原子更新，不以某一執行個體的部分線路快照覆蓋其他 key。診斷欄位 cacheState 及少量 unmappedExamples 供來源核對；未知路徑繼續暫不繪製。

多車持續場景以約 20fps 的 repaint timer 推進，跟車採短間隔真實時鐘位置更新；初次取景仍可平滑縮放。此為減少持續 GPU 負擔，並非把實時時鐘加速或降速。

## 已觀察到的資料差異（02:00–02:07 UTC）

官方港島線回應 status1，但 curr_time/sys_time 是 `-`，沒有班次；正規化為「暫未有有效預報」，不捏造資料時間，也不認定停駛。其他線依實際資料繼續顯示。

另見 KTL DOWN→HOM、TML UP→MEF、TML DOWN→DIH，超出字典 v1.7 的目的地表，但各自位於已驗證方向軌道之後。三個明確例外記在 data/config/destination-overrides.json，附 source/reason，仍逐項驗證站序與原始幾何；不泛化為任意終點容錯。TML 兩項有原始回應，KTL HOM 有帶時戳的官方 proxy cache 證據及稍後 WHA-only 原始回應，來源邊界在各檔明示。短途動畫到指定終點就結束，不延長到 TUM／WKS／WHA。未知新目的地繼續列入 unmappedExamples，暫不繪製。

正式 Worker 的 fetch promise、timeout 與 semaphore 只屬於當次 HTTP 請求，不跨請求共用；跨請求只保留限速／退避數值，資料與虛擬 ID 從 D1 還原。這避免前一請求結束後，後續請求等待已被雲端取消的 I/O。Node 常駐服務可繼續使用 process 內請求合併。
